### 검증 — 대비 4.5:1

색을 눈으로 고르지 않고 oklch→sRGB→WCAG 상대휘도로 계산해서 골랐다. 배경은 배지가 실제로
깔고 앉는 **10% 틴트**로 잡았다(순수 배경 대비로 재면 통과인데 실제로는 미달하는 값이 나온다).

검증 명령: `docs/DESIGN.md` §1의 oklch 값들을 아래 스크립트에 넣고 실행
(엔진 의존성 0 원칙에 따라 파이썬 표준 라이브러리만, 레포에 남기지 않음 — 이 티켓은 문서다).

```
$ python3 - <<'EOF'   # oklch -> sRGB -> WCAG 상대휘도 대비
...
EOF
토큰 대비 (텍스트=토큰, 배경=토큰 10% 틴트) — AA 기준 4.5
  --status-active    라이트 4.89 / 다크 7.64
  --status-assigned  라이트 5.21 / 다크 7.66
  --status-blocked   라이트 4.89 / 다크 9.05
  --status-done      라이트 4.85 / 다크 8.50
  --status-stale     라이트 5.17 / 다크 7.40

반례 (스펙이 금지한 조합)
  --muted-foreground on --muted   라이트 4.34 / 다크 5.83
  --destructive 10% 틴트           라이트 3.99 / 다크 6.19
  --destructive 솔리드 + 흰 글씨    라이트 4.76 / 다크 2.89

판정: PASS — 상태 토큰 5개 x 2모드 전부 >= 4.5
```

반례 3줄이 이 티켓의 실제 산출물이다. shadcn 기본값을 그대로 믿었으면 셋 다 AA를 깨고 나갔다.
그래서 §1에 "`--muted-foreground`를 배지 텍스트로 쓰지 않는다", "`--destructive`는 파괴적
액션 전용, stale에 재사용 금지"를 못으로 박았다. `--status-done`은 첫 후보 `L=0.52`가
틴트 위에서 4.49로 아슬하게 미달해 `L=0.50`으로 내렸다.
