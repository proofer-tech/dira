# 외부 계정의 리소스를 만드는 길

주도성 안내가 오토파일럿일 때 적용한다. 이미 로그인된 계정에 저장소, 토큰, 환경변수, 연결을 새로
만드는 일은 권한 안이고, "남의 계정이라 범위 밖"은 멈출 사유가 아니다. 정본은 `docs/DESIGN.md`
§P562 결정 2와 3이다.

## 순서: 앞 칸이 안 되면 다음 칸으로 간다

1. **CLI 명령.** `vercel`, `gh`, `supabase`처럼 이미 로그인된 CLI를 먼저 쓴다. `<명령> --help`로 만드는
   하위 명령을 찾는다.
2. **CLI가 저장한 토큰으로 REST API.** CLI에 해당 명령이 없을 때 쓴다. 토큰은 아래 표의 위치에서 읽어
   명령의 환경변수로만 넘긴다. 티켓, 커밋, 로그에 값을 적지 않는다.
3. **`.dira/browse.sh` 풀 슬롯의 대시보드.** 사람이 한 번 로그인해 둔 프로필을 그대로 쓴다.
   로그인 화면이 뜨면 이 칸은 실패로 치고 다음 방법(다른 계정, 범위 조정)으로 간다. 사람의 크롬
   프로필에는 붙지 않는다(`cdp.md`).

세 칸을 다 시도한 뒤에만 `autopilot_failed`가 정당하다.

## 토큰 위치 (이 머신에서 2026-11-12에 실측)

| 도구 | 위치 |
|---|---|
| `vercel` | `~/Library/Application Support/com.vercel.cli/auth.json`의 `token` 키 |
| `gh` | `gh auth token` 명령의 출력(파일은 `~/.config/gh/hosts.yml`) |
| `supabase` | 키체인 서비스 `Supabase CLI`(없으면 `~/.supabase/access-token` 파일) 또는 환경변수 `SUPABASE_ACCESS_TOKEN`. 이 머신은 지금 로그인되어 있지 않아 둘 다 비어 있다 |

키체인은 `security find-generic-password -s "<서비스>"`로 항목 하나만 조회한다. `dump-keychain`으로
전수 조회하면 항목마다 동의 팝업이 떠서 화면이 막히므로 금지다.

## 하지 않는 것 둘

- 결제 수단 입력이나 요금제 상향
- 이미 있는 데이터의 삭제나 덮어쓰기

## 만든 뒤에 `## 결과`에 적는 것

무엇을 어디에 만들었는지와 **되돌리는 명령**을 적는다. 예: `vercel blob delete-store <저장소 id>`.

## 예시: `d206439f` (Blob 저장소가 없던 경우)

1. `vercel blob create-store <이름> --access private`로 저장소를 만든다.
2. 저장소를 프로젝트에 연결한다. 프로젝트 디렉터리에서 `vercel link`를 한 뒤 `create-store`를 돌리고 `--environment`로 연결할 환경을 고르면 한 번에 된다.
3. `vercel env pull`로 새 환경변수를 받아 쓴다.
