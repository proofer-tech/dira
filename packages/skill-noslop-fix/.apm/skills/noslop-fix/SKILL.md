# noslop-fix

슬롭은 한 번 들어오면 인용을 타고 번진다. 발견한 자리에서 처리하는 습관이 파이프라인의 마지막 노드다.

## 반사 규칙 (작업 중)

어떤 작업이든 파일을 읽었을 때 다음을 한다. 읽은 파일이 md, txt, docx, pptx 이고 한국어 산문이면 대상이다.

1. `python3 -m noslop score 파일` 을 돌린다. 임계(기본 40) 미만이면 아무것도 하지 않는다.
2. 임계 이상이면 backlog 에 한 줄 적는다. 위치는 저장소 루트의 `.noslop/backlog.md`, 저장소가 아니면 `~/.noslop/backlog.md`.

```
- 2026-09-16 | vault/objects/projects/x.md | score 58 | B02,B04,R05,R07 | 발견 맥락: 뉴스레터 초안 참조 중
```

3. 소유를 판정한다.
   - 내 파일(내 저장소, 내 vault, 내가 쓴 초안): 지금 하던 작업을 끝낸 뒤 **별도 커밋**으로 고친다. 커밋 메시지는 `noslop: <파일> B02,B04 제거` 형식. 하던 작업의 커밋에 섞지 않는다.
   - 남의 글(게스트 원고, 동료 문서, 외부 자료): 고치지 않는다. 제안 diff 를 만들어 채팅이나 코멘트로 건넨다. 원문을 덮어쓰지 않는다.
   - 회사 vault 의 문서: 내가 작성자면 내 파일로, 아니면 남의 글로 다룬다.
4. 고칠 때는 `noslop-review` 절차를 그대로 쓴다. 반사 규칙이라고 해서 감사 패스를 건너뛰지 않는다.
5. 고친 뒤 backlog 줄에 `-> 처리 (커밋 해시)` 를 붙인다.

하던 작업을 멈추고 고치러 가지 않는다. 적어 두고, 끝나고 돌아온다. 긴급한 것은 없다.

## 참조 격리와의 관계

`noslop-write` 2단계에서 격리된 파일은 자동으로 backlog 대상이다. 격리는 "지금 이 글에 문체를 옮기지 않는다"이고, fix 는 "나중에 그 파일 자체를 고친다"이다. 둘 다 한다.

## 주기 점검 (sweep)

주 1회, 또는 사용자가 부르면:

```
python3 -m noslop sweep <디렉터리> --top 10
```

- 점수 높은 순으로 10개가 나온다. `Q` 표시가 격리 임계 이상이다.
- 결과를 티켓 하나로 만든다. 사용자가 Multica 나 이슈 트래커를 쓰면 그쪽에, 아니면 backlog 에 절을 추가한다. 티켓 본문은 파일, 점수, 규칙 ID, 한 줄 요약만. 작업 보고체를 쓰지 않는다.
- 사람이 쓴 글이 상위에 올라오면 규칙 오탐이다. 그 파일을 `eval/golden/` 에 넣고 `python3 eval/run_eval.py` 로 어느 규칙이 걸리는지 본다. 오탐률 1% 넘는 BLOCK 규칙은 REVIEW 로 내린다. 이 갱신은 rules.yaml 한 곳에서만 한다.

## 예약 실행 (선택)

Claude Code 나 Cowork 의 예약 작업으로 매주 월요일 아침에 sweep 을 돌리고 결과를 티켓으로 남기게 할 수 있다. 프롬프트 예:

> `~/Projects/<repo>` 에서 `python3 -m noslop sweep . --top 10` 을 실행하고, 격리 임계 이상 파일이 있으면 `.noslop/backlog.md` 에 오늘 날짜 절로 추가한 뒤 이슈 트래커에 티켓 하나를 만들어라. 파일 본문은 고치지 말라.

## 하지 않는 것

- 남의 글을 허락 없이 덮어쓰기.
- 하던 작업의 커밋에 슬롭 수정을 섞기.
- 점수만 보고 "AI가 썼다"고 말하기. 점수는 문체 신호의 합이지 저자 판정이 아니다.
