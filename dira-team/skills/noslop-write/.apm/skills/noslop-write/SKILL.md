# noslop-write

슬롭은 지우는 것보다 안 쓰는 것이 싸다. 이 스킬은 생성 단계에서 슬롭이 들어오는 세 경로를 순서대로 막는다. 규칙의 정본은 `rules/rules.yaml` 이고, 이 문서는 절차만 적는다.

## 0. 준비

- 린터 위치를 확인한다. `python3 -m noslop --help` 가 돌면 된다. Cowork 에서는 Desktop Commander 로 호스트에서 실행한다 (`cowork/README.md`).
- 개인 프로필(`~/.noslop/profile.yaml`)이 있으면 자동으로 얹힌다. 없어도 정본 규칙만으로 동작한다.

## 1. 매체를 먼저 확정한다

매체가 정해지지 않으면 어미, 길이, 서식 허용도가 전부 틀어진다. 사용자가 안 밝혔으면 묻는다. 매체 이름은 rules.yaml 의 registers 키를 그대로 쓴다.

| 매체 | 어미 | 서식 | lint 옵션 |
|---|---|---|---|
| prose | 글에 맞게 하나로 고정 | 볼드 5개 이하, 불릿 최소, 이모지 0 | `--register prose` |
| docs | ~한다 / ~하였다 | 헤딩, 표, 불릿 허용. 첫째둘째 허용 | `--register docs` |
| social | ~습니다 + ~요 혼용 허용 | 이모지 3개까지, 한 줄 문단 허용 | `--register social` |
| chat | ~요 / ~습니다 | 짧게. 볼드 불릿은 훑어야 할 때만 | `--register chat` |
| formal | ~습니다 일관 | 평문. 마크다운 구조 0 | `--register formal` |

## 2. 참조 자료를 격리한다 (증폭 차단)

vault 노트, 이전 산출물, 검색 결과, 남이 준 원고를 읽을 때 문장을 옮기면 그 문체가 따라온다. 이걸 막는 절차다.

1. 참조 파일마다 `python3 -m noslop score 파일` 을 돌린다.
2. 점수가 격리 임계(기본 40) 이상이면 그 파일에서 **문장을 인용하지 않는다.** 대신 아래 형식의 중립 목록을 만든다.

```
[사실] 2026-08-14 발표자 노트에서 개수 예고 42건 지적받음 (출처: vault/.../x.md L12)
[수치] 참가자 25팀 중 7곳 (출처: ...)
[판단-원문] "이 방식은 실패했다" 라는 저자 판단이 있음. 근거는 적혀 있지 않음
```

3. 초안은 이 목록만 보고 쓴다. 원문은 다시 열지 않는다. 점수가 임계 미만이면 짧은 직접 인용은 허용하되 큰따옴표로 감싸고 출처를 단다.
4. 참조 자료가 내 소유 파일이고 점수가 임계 이상이면 `noslop-fix` 반사 규칙에 따라 backlog 에 적는다. 지금 고치지는 않는다.

이 단계를 건너뛰면 사후 윤문으로는 못 돌린다. 변경률 30% 게이트에 걸리기 때문이다.

## 3. 무색 초안을 쓴다

사실, 사람, 동사만 남긴 초안이다. 이 단계에서는 장식을 넣지 않는다.

- 첫 문장부터 내용이다. 예고문, 헛기침, "이 글에서는" 을 쓰지 않는다.
- 행위자를 주어로 쓴다. 누가 했는지 못 쓰면 그 문장을 지운다.
- 개수를 세어 붙이지 않는다. 첫째둘째 라벨을 붙이지 않는다 (docs 는 예외).
- "A가 아니라 B" 를 쓰지 않는다. B만 쓴다.
- 문단 끝을 교훈 한 줄로 닫지 않는다. 마지막에 결론적으로, 요약하면을 쓰지 않는다.
- 정도 부사(매우, 굉장히, 상당히)를 넣지 않는다. 지워서 뜻이 그대로면 장식이다.
- 문장 성분과 조사, 어미는 채운다. 덜어낼 것은 장식이지 통사 구조가 아니다.
- 키보드에 있는 부호만 쓴다. 줄표, 화살표, 낫표는 처음부터 치지 않는다.

## 4. 보이스를 입힌다 (선택)

개인 문체 스킬(예: 본인의 writing 스킬)이 있으면 이 단계에서만 적용한다. 무색 초안 위에 얹는다. 순서를 바꾸면 안 된다. 보이스부터 쓰면 그 밑에 깔린 슬롭 골격이 lint 에서 안 잡힌다.

보이스가 되살려도 되는 것은 개인 스킬의 허가표를 따른다. 허가표가 없으면 되살리지 않는다.

## 5. lint 를 통과시킨다

```
python3 -m noslop lint 산출물.md --register <매체>
```

- BLOCK 이 하나라도 있으면 고치고 다시 돌린다. 사실과 수치는 건드리지 않는다.
- REVIEW 는 하나씩 남길 이유를 정한다. 이유가 없으면 고친다. 이유가 있으면 그대로 두고 상태 줄에 적는다.
- pptx 와 docx 는 파일 자체에 돌린다. pptx 는 발표자 노트까지 검사된다.
- 통과 전에는 산출물을 내지 않는다. 사용자가 급하다고 해도 게이트는 유지하고 반복 횟수를 줄인다.

## 6. 결과를 낼 때

상태 한 줄만 붙인다. 예: `noslop: BLOCK 0 / REVIEW 2 (R03 종결어미 4연속은 인용문 때문, R10 제목 숫자는 독자가 쓰는 값)`.

산출물 본문에 작업 보고를 섞지 않는다. 몇 개를 읽었고 어디에 적었는지는 채팅에만 쓴다.

## 하지 않는 것

- 원문에 없던 비유, 수사, 사례를 윤문 과정에서 넣지 않는다.
- 사용자의 어조를 따라 산출물 어미를 바꾸지 않는다. 반말로 지시해도 매체표가 정한 어미를 쓴다.
- 탐지기 우회를 목적으로 쓰지 않는다. 사실을 가리는 방향으로는 절대 고치지 않는다.
