# 폴링 대기 - 조건을 기다리는 티켓은 워커를 반납하고 열린 채로 기다린다

정본은 `docs/DESIGN.md` §폴링 대기(요구 `a6335308`)다. 여기에는 세션이 매 디스패치마다
알아야 하는 사항만 간추려 둔다.

## 언제 이 길인가

셋 다 턴을 붙들지 않고 기다리지만, 기다리는 주체가 서로 다르다.

| 갈래 | 기다리는 주체 | 쓰는 자리 |
|---|---|---|
| 턴 안 폴링 | 살아 있는 세션 | 결과를 몇 분 안에 받을 수 있을 때뿐(`AGENTS.md` §턴을 닫으면 - 상한 없는 블로킹 대기 금지, 실측 `세션-종료.md`) |
| 이어받기 한 장 | 다음에 뜨는 새 세션 | `## Done when`이 안 끝났는데 이번 턴을 닫아야 할 때 |
| 폴링 대기 | 큐에 열린 티켓 자체 | 외부 조건(빌드-배포-사람이 넣는 값)이 몇 십 분-몇 시간 뒤에 옴 |

## 턴 안 폴링의 `until` 예 - 백그라운드 출력 파일

백그라운드로 실행한 명령의 출력 파일이나 dev 서버 로그에 내용이 쌓이기를 기다릴 때는 상한을
둔 `until`을 쓴다. 고정 `sleep`은 쓰지 않는다. 상한을 넘기면 그 자리에서 결과를 억지로
기다리지 않고 §미완으로 끝날 때의 이어받기 절차로 넘긴다(`AGENTS.md`). **`## 블록`이
아니다** - 사람이 답할 것이 없다.

```bash
OUT=/private/tmp/claude-.../tasks/<id>.output
DEADLINE=$(( $(date +%s) + 300 ))
until [ -s "$OUT" ] || [ "$(date +%s)" -ge "$DEADLINE" ]; do
  sleep 5
done
if [ "$(date +%s)" -ge "$DEADLINE" ]; then
  echo "상한 300초 초과 - 이어받기 한 장을 내고 닫는다" >&2
else
  tail -60 "$OUT"
fi
```

## 여는 문 - `poll` 서브커맨드

```
.dira/workers/<w>.sh poll <내 해시> <스크립트 파일명> <상한 ISO 8601>
```

검사 다섯 - 하나라도 걸리면 fm을 한 글자도 안 고치고 0이 아닌 코드로 거절한다.

1. 스크립트가 `<루트>/polls/<파일명>`에 있고 실행 권한이 있다. 값에 `/`가 없다.
2. `# dira-poll-interval:` 줄이 있으면 값이 양의 정수다.
3. `<상한>`이 파싱되고 지금보다 뒤다.
4. 그 티켓의 주인이 자기 세션이다.
5. 그 자리에서 한 번 돌려 종료 코드가 `0`이면(이미 도달) 대기에 안 넣고 그대로 둔다.

## 스크립트 계약

첫 줄에 `# dira-poll-interval: <초>`를 적는다(없으면 매 tick마다 돌린다). 종료 코드 `0`은
대기 해제, `1`은 유지, 그 밖(실행 상한 초과로 죽인 경우 포함)은 `polling_fails`를 올린다 -
3에 도달하면 아래 §상한을 넘기면과 같은 처리로 넘어간다. **실행 상한 30초** - 넘기면 죽이고
오류 1회로 센다. stdout-stderr를 합친 마지막 200줄이 `polls/<해시>.log`에 남는다.


## 상한을 넘기면

`polling_until`을 지난 tick이 그 자리에서 `ask_human`을 부른다. `awaiting`이 걸리고 본문
마지막 절이 `## 질문 n`이며, 그 절에 마지막 폴링 출력이 인용으로 들어간다. 선택지 셋 -
상한 연장 / 즉시 디스패치 / 티켓 닫기.

## 금지 - 명령

- **`## 블록`을 쓰지 않는다** - 사람이 답할 것이 없다. 상한이 지나면 엔진이 알아서 `ask_human`을
  부른다.
- **`## 결과`에 무엇을 기다리는지와 상한을 적고, 사유는 그 절 첫 줄에 한 문장으로 쓴다**
  (화면이 배지 아래에 그대로 표시한다, §개정 2). 진행 계획 항목은 미리 체크하지 않는다 -
  조건이 오면 같은 티켓이 다시 뜨고 그때 이어서 체크한다.
