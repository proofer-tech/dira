# 워크트리와 git 흐름 - 경위와 근거

인라인 `AGENTS.md` §당신이 있는 곳과 §git - 시작 - 끝에 규칙과 명령이 있다.
이 문서는 그 배치가 왜 그렇게 됐는지다.

## 왜 워커마다 워크트리인가

cwd는 `~/Projects/dira/.dira/worktrees/<워커>`, 이 레포의 **git 워크트리**다(브랜치
`wt/<워커>`). 워커마다 자기 워크트리가 있어 동시에 도는 두 세션이 같은 파일을 서로 덮어쓰지 않는다.

경로가 손으로 적는 값이던 시절 **세 세션이 한 트리에 커밋한 사고**가 있었다(2026-07-30).
유도로 바꾼 스펙이 `6d6f6823`이다.

## 무엇이 어디 있나

| 여기 있는 것 | 성격 |
|---|---|
| `docs/` `apps/teams/` `README.md` | 워크트리의 **자기 사본**. 여기서 고치고 커밋한다 |
| `.dira/` | **심링크 -> canonical 큐 1개.** gitignore - 커밋 대상이 아니다 |
| `tick.sh` `tickets.py` `test_*.py` | 엔진. **읽기 전용** |

큐 사본은 세상에 하나뿐이다(`~/Projects/dira/.dira`). `git status`에 티켓이 안 뜨는 것이
정상이다. 심링크는 상대경로 `../..`라 자기 조상을 가리키고 무한히 재귀한다 - **워크트리
루트에서 `find -L`-`grep -R`을 돌리지 않는다.**

## push 헬퍼

`bash .dira/push.sh`가 통합 push의 벽이다(`06d2fc41`). 헬퍼는 rebase를 안 한다 - 받는
트리(`~/Projects/dira`) 하나만 다루고, 지금 서 있는 워크트리는 건드리지 않는다.

- non-fast-forward 거부 -> `git rebase master` 후 재시도. 충돌은 **자기 티켓 범위만**
  해결한다. 3회 실패하면 `## 블록`이다.
- 헬퍼가 락 상한(120초)을 넘거나, 되돌리기에 실패하거나, 헬퍼가 없는 프로젝트라고 거부하면
  `push-거부.md`를 읽는다 - 셋 중 하나만 즉시 `## 블록`(락 상한)이고, 하나는 블록 없이
  `## 결과`에 한 줄만 남기고(되돌리기 실패), 나머지 하나(헬퍼가 없는 프로젝트)는 옛 절차대로
  판정한다. 블록에는 브랜치와 커밋 해시를 적고 **빨리 끝낸다** - 이 상태가 풀리지 않는 동안
  워커 전부의 디스패치가 멈춘다.
- 금지: `push --force`, `reset --hard`, `stash`, 원격(origin) push. 사람이 한다.
  (`.dira/push.sh` 내부의 stash는 헬퍼가 받는 트리에서 스스로 하는 것이라 이 금지의 대상이
  아니다.)

## 통합 체크아웃에서 일한 예외 - `Exception:` 한 줄

세션이 뜨는 곳은 자기 워크트리이고, 받는 트리(`~/Projects/dira`)에서 커밋을 내는 것은
예외다. 예외가 실제로 필요했으면 **숨기지 말고 표기한다.** 계약은 `docs/DESIGN.md`의
'워커는 언제나 자기 워크트리에서 일한다' 절, 개정 4다.

- **형식**은 커밋 메시지의 `Exception: <사유>` 한 줄이고, 위치는 `Ticket:` 줄과 같은
  트레일러 문단이다.
- **적는 곳**은 `bash .dira/push.sh ship <해시> "<제목>" "<본문>"`의 `<본문>` 마지막 줄이다.
  **`ship`에 새 플래그를 만들지 않는다** - 만들면 예외를 내는 경로가 두 벌이 된다.
- **사유**는 *왜 워크트리에서 할 수 없었나* 한 문장이다. `긴급`이나 `임시`는 이유를 담고 있지
  않으므로 사유가 아니다.
- **사람이 직접 내는 커밋은 대상이 아니다.** 판정은 `Ticket:` 트레일러의 유무 하나이고, 사람이
  낸 커밋에는 그 줄이 없어서 애초에 후보로 잡히지 않는다.
- **커밋 메시지에만 남기는 것은 금지다** - `## 결과`에 그 커밋 해시와 사유를 같이 적는다.
  메시지에만 두면 티켓을 읽는 사람이 그 사실을 못 본다.

표기를 뺀 세션 커밋은 `bash .dira/push.sh drift`가 한 줄씩 센다. 세기만 하고 막지도 되돌리지도
않으므로, 표기를 빠뜨리면 아무 경고 없이 그 목록에 남는다.

## 커밋이 실패했을 때 - 어느 트리에서 실패했나로 갈린다

`git rebase`도 push도 아닌 `git commit` 자체가 실패한 경우다. 계약은 위 절이 가리킨 그 절의
개정 5이고, 갈래는 둘이다. 판정하는 한 줄은 `git rev-parse --git-common-dir`다 - `.git` 하나로
나오면 받는 트리에 있는 것이고, 워크트리에서는 절대경로가 나온다.

**(1) 받는 트리에서 실패했으면 원상복구가 먼저다.** 순서는 셋이고 뒤집지 않는다.

```
git diff <파일> > /tmp/<티켓 해시>.patch     # 내 편집을 먼저 뜬다
git restore <파일>                           # 받는 트리를 원래대로
cd <내 워크트리> && git rebase master && git apply /tmp/<티켓 해시>.patch
```

**diff를 뜨기 전에 지우는 것은 금지다** - 위 세 줄을 순서대로 돌리고, 복구한 사실과 그 커밋을
시도한 위치를 `## 결과`에 적는다. `git reset --hard`도 `git stash`도 안 쓴다 - 그 트리에 사람의
미커밋 편집이 같이 있을 수 있고 stash 스택은 워크트리 전부가 나눠 쓴다.

**(2) 자기 워크트리에서 실패했으면 첫 실패에 `## 블록`이다.** push의 3회 규칙을 여기로 가져오지
않는다 - push가 셋을 허용하는 이유는 다른 워커와의 경쟁이고, 커밋에는 그 경쟁이 없어서 재시도해도
같은 지점에서 같은 오류가 난다. **두 번째 `git commit`을 시도하는 것이 금지이고**, 그 대신
곧바로 `## 블록`을 쓰며, `git commit`의 stderr를 거기 그대로 붙인다.

두 갈래 다 통합 브랜치에 흔적을 안 남긴다 - (1)은 남은 흔적을 제거하고, (2)는 자기 브랜치 위에서
실패하므로 남길 흔적이 없다.

## 시작에 만난 미커밋 변경

`git rebase master`가 더러운 트리에 막히면 순서가 이렇다.

1. 받은 티켓에 `## 결과`-`## 블록`이 붙어 있으면 재디스패치이고 이 절이 아니다 -
   §재디스패치를 알아보는 방법으로 간다.
2. 변경된 파일 이름으로 `.dira/tickets/*.md`를 grep해 주인 티켓을 찾는다.
3. 주인 티켓이 `.wip`이거나 아직 배정되지 않았으면 **버린다** - `git restore .`과 미추적 파일
   삭제. 그 티켓은 다시 디스패치되고 그 세션이 다시 쓴다.
4. 주인 티켓이 `.done`인데 그 산출물이 master에 없거나, 주인을 못 찾으면 **보존한다** -
   `git tag orphan/<워커>/<UTC 초> $(git stash create)`를 돌리고 `git restore .`.
5. 보존했으면 **후속 티켓 한 장**을 낸다. `persona:`는 주인 페르소나로 하고, 본문에 태그
   이름과 `git show --stat <태그>`를 적는다. **티켓 없이 보존한 것은 보존이 아니다.**

금지 셋 - `git stash push`(공유 스택이라 남의 것을 pop한다), master에 WIP 커밋(워커 전부가
다음 rebase에서 절반을 받는다), 큐 밖의 임시 파일(`~/.config/dira/*.patch` 등, 큐에 없으면
아무도 못 찾는다). 근거는 `docs/DESIGN.md` §프롬프트 층 결정 12.

## 재디스패치를 알아보는 방법

받은 티켓에 `## 결과`-`## 블록`이 이미 붙어 있으면 재디스패치다 - **그 글은 주장이고 검증
출력이 아니다.** 적힌 커밋 해시를 믿지 말고 산출물이 master에 있는지 **내용으로** 확인한다
(`git log --oneline master -- <파일>` 또는 `grep`). 없으면 앞 세션의 작업이 다른 워커 트리에
살아 있다 - `재디스패치-복구.md`를 읽고 그대로 한다(트리 훑기-patch 회수-정리).
