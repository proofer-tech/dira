# 설치

[최신 릴리스](https://github.com/proofer-tech/dira/releases/latest)에서 `.dmg`를 받아 열고
`dira.app`을 `응용 프로그램`으로 끌어다 놓으세요. 업데이트는 앱이 스스로 받습니다.

## 필요한 것

준비할 것은 둘입니다. 지금 하나도 없어도 순서대로 따라오시면 됩니다.

### 1. Apple Silicon 맥

앱은 여기서만 돕니다. 화면 왼쪽 위 사과 메뉴에서 `이 Mac에 관하여`를 열어 보세요. `칩`이
`Apple M`으로 시작하면 맞습니다. Intel 맥이라면 앱을 쓸 수 없습니다. 그 경우 아래
[앱 없이 엔진만 쓰기](#앱-없이-엔진만-쓰기)로 가세요.

### 2. 엔진 설정하기

dira를 돌리려면 CLI로 부르는 LLM 엔진이 하나 있어야 합니다. 워커가 티켓을 맡아 띄우는 세션이
이것이라, 없으면 티켓이 `대기`에서 움직이지 않습니다. 기본값은
[`claude`](https://claude.com/claude-code)입니다.

방금 옮겨 놓은 `dira.app`을 열고 헤더 오른쪽 끝의 `설정`을 누르세요. `인증`의 `claude` 항목에서
맨 윗줄을 봐주세요. 설치돼 있으면 `claude CLI —` 뒤에 앱이 찾은 경로가 붙습니다. 없으면
`claude CLI를 찾지 못했습니다 — 워커가 세션을 띄우지 못합니다`라고 나옵니다.

엔진을 설치하고 나면 앱을 껐다가 다시 열고 같은 자리를 보세요. 앱이 프로그램을 탐색할 경로
목록은 앱이 켜질 때 한 번 정해집니다. 그 줄이 경로로 바뀌어 있으면 준비가 끝났습니다.

워커가 티켓을 맡아 이 엔진을 실행하는 동안 macOS가 권한이나 키체인 접근을 물어올 수 있습니다.
그 창에는 dira라는 이름 대신 숫자(예: `2.1.222`)가 뜹니다. 워커가 방금 설정한 CLI 엔진을
그대로 실행하기 때문입니다. 낯선 프로그램이 뜬 상황은 아닙니다. 그 엔진 자신이 필요해서 띄우는
창이니 허용해 주시면 됩니다.

`python3`와 `bash`는 macOS에 이미 있습니다. 엔진이 쓰는 것은 그 둘의 표준 라이브러리뿐이라
따로 설치할 패키지가 없습니다. 예외가 하나 있습니다. 페르소나와 스킬을 패키지로 까는 `apm`인데,
이것은 dira가 직접 깝니다. 아래 §패키지 설치 - apm을 보세요.

## 패키지 설치 - apm

저장소에 `dira-team/apm.yml`이 있는 프로젝트는 페르소나, 스쿼드, 프로토콜, 스킬을
APM 패키지로 받습니다. 무엇을 받는지는 그 `apm.yml`이 정하고,
정확히 어느 버전을 받았는지는 옆의 `dira-team/apm.lock.yaml`이 고정합니다. 둘 다 커밋되는
파일이라 다른 기계에서 clone해도 같은 내용이 깔립니다. 앱 업데이트가 등록 프로젝트를 이 배치로
옮기며, dira 프로젝트가 먼저 옮겨지고 나머지는 검증이 끝난 뒤에 옮겨집니다.

**apm CLI는 dira가 깝니다.** 사용자 PATH에 있는 `apm`은 쓰지 않습니다. 엔진 파일 `apm-version`에
적힌 버전(지금 `0.33.0`)을 `~/.config/dira/tools/apm/<버전>/`에 따로 깝니다. apm은 Python 3.10
이상이 필요한데 macOS의 `python3`는 그보다 낮을 수 있습니다. 그래서 `uv`가 있으면
`uv tool install --python 3.12 apm-cli==<버전>`으로 깔고, 없으면 3.10 이상인 `python3.x`를 찾아 그
디렉터리에 venv를 만듭니다. 둘 다 없으면 설치가 실패하므로 `uv`를 먼저 깔아 두는 편이 간단합니다.

### 새 기계에서 설치하기

프로젝트 저장소를 clone한 뒤 명령 하나를 돌립니다. apm CLI가 없으면 그것부터 깔고, lock대로
패키지를 깐 다음 설치 결과를 검사합니다.

```bash
python3 dira_apm.py install <프로젝트 루트>
```

`dira_apm.py`는 엔진 저장소 루트에 있습니다. 앱만 쓰신다면
`~/Library/Application Support/dira/engine/` 안에 있습니다. 앱을 쓰면 이 명령을 직접 칠 일이
드뭅니다. 워커가 claim하기 전에 설치 상태를 확인하고, lock과 다르면 스스로 한 번 설치하기
때문입니다.

### `멈춤: 패키지 설치 상태가 lock과 다릅니다`가 뜨면

워커가 스스로 설치를 시도했는데도 설치 결과가 lock과 맞지 않으면, 그 프로젝트는 티켓을 가져가지
않고 멈춥니다. 상태 표시줄 시계 뒤에 `멈춤: 패키지 설치 상태가 lock과 다릅니다`가 붙고, 그 프로젝트의
`runner.log`에는 아래 줄이 남습니다. 대시 뒤에는 어긋난 내용이 한 줄로 요약됩니다.

```text
SKIP apm 설치 상태가 lock과 다르다 - <요약 한 줄>
```

할 일은 설치 명령을 직접 돌려 보는 것입니다.

```bash
python3 dira_apm.py install <프로젝트 루트>
```

이 명령은 어긋난 곳마다 한 줄씩 출력합니다. 흔한 경우는 셋입니다.

- apm CLI를 깔지 못했습니다. `uv`나 Python 3.10 이상이 이 기계에 있는지 보고, 없으면 깔고 다시
  돌립니다.
- 같은 이름의 스킬이 두 패키지에서 옵니다. 출력에 두 패키지 이름이 적힙니다. 한쪽 페르소나에서 그
  스킬을 빼거나 이름을 바꾸고 다시 돌립니다.
- `dira-team/apm_modules/` 안의 파일을 누군가 손으로 고쳤습니다. 설치 명령이 lock대로 다시 깔면
  풀립니다.

명령이 문제없이 끝나면 다음 tick부터 그 프로젝트가 다시 티켓을 가져갑니다.

## 업데이트한 뒤 화면이 흐려졌을 때

> 2026-10-16 현재 이 화면은 아직 구현 중입니다. 아래 `migrate.py` 명령은 지금도 쓸 수 있습니다.

업데이트 중에는 프로젝트 폴더의 파일 형식이 바뀌는 경우가 있습니다. 그러면 앱을 다시 열었을 때
화면 전체가 흐려지고, 그 위에 `dira를 업데이트하는 중입니다` 창이 뜹니다. 고장이 아닙니다.
등록한 프로젝트를 새 형식으로 하나씩 옮기는 중이고, 다 끝나면 창이 저절로 닫힙니다. 그동안에는
아무것도 누르지 말고 기다리세요. 옮기는 동안에는 어느 프로젝트에서도 워커가 새 티켓을 가져가지
않습니다.

창에는 프로젝트마다 한 줄이 있습니다. 회색 점은 차례를 기다리는 중이고, 스피너 옆에는 지금
적용하는 항목이 보이며, 체크 표시는 끝났다는 뜻입니다. `진행 중인 세션 {n}개가 끝나기를
기다립니다`가 보이면 그 프로젝트에서 아직 돌고 있는 세션이 있다는 뜻입니다. 세션을 끊지 않고
끝날 때까지 기다린 다음에 옮깁니다. 20분이 넘으면 버튼 둘이 나옵니다. 세션이 곧 끝날 것 같으면
`20분 더 기다리기`를, 그 프로젝트를 나중에 처리하려면 `이 프로젝트 건너뛰기`를 누르세요.

**실패한 줄이 있으면** 그 줄에 원인 한 줄, 로그 경로, 백업 경로가 나옵니다. 실패한 프로젝트는
바뀌기 전 상태로 이미 되돌려져 있고, 다른 프로젝트는 그대로 계속 진행됩니다. 원인 줄을 읽고
고칠 수 있는 문제(디스크가 꽉 찼다든지)였다면 고친 뒤 `다시 시도`를 누르세요. 원인을 모르겠거나
지금 시간을 쓰기 싫으면 `이 프로젝트 건너뛰기`를 누릅니다. 건너뛴 프로젝트는 줄에
`건너뜀 - 이 프로젝트는 디스패치하지 않습니다`가 붙고, 그 프로젝트의 티켓은 다시 적용할 때까지
아무도 가져가지 않습니다. 나머지 프로젝트는 평소대로 돕니다.

**백업**은 프로젝트마다 `<프로젝트>/.dira/migrations/backup/<항목 ID>/<시각>/`에 남습니다. 바뀌기
전 파일이 zip으로 묶이지 않은 원본 그대로 프로젝트 안 위치 그대로 들어 있습니다. dira는 이 폴더를
지우지 않으니 필요 없어지면 직접 지우세요. 무엇을 했는지는
`<프로젝트>/.dira/migrations/migrate.log`에 시각과 함께 한 줄씩 적혀 있습니다.

**건너뛴 프로젝트를 나중에 적용하려면** 터미널에서 아래처럼 실행합니다. 앱에 들어 있는 엔진은
`~/Library/Application Support/dira/engine/`에 있습니다. `<루트>`는 그 프로젝트의 `.dira`
폴더입니다.

```bash
cd ~/Library/Application\ Support/dira/engine
python3 migrate.py list --root <루트>                 # 건너뜀으로 남은 항목 ID를 확인한다
python3 migrate.py apply --root <루트> --id <항목 ID>  # 그 항목을 적용한다
```

건너뛴 항목이 여럿이면 ID마다 한 번씩 실행합니다. `--id` 없이 `apply`를 실행하면 건너뛴 항목은
그대로 남습니다. 남은 항목이 모두 적용되면 그 프로젝트도 다시 디스패치됩니다. 명령 전체는
[CLI](/docs/ref-cli#migrate-py-프로젝트-마이그레이션)에 있습니다.

## 앱 없이 엔진만 쓰기

화면이 필요 없거나 Linux에서 돌리실 때입니다. 이 경우에는 레포를 직접 받습니다.

```bash
git clone https://github.com/proofer-tech/dira.git ~/Projects/dira
```

워커 파일을 손으로 만들고 cron에 거는 절차는 부록 [엔진만으로 돌리기](/docs/cron)에 있습니다.
앱을 같이 쓰셔도 상관없습니다. 앱은 자기 몫의 엔진을 번들 안에 따로 포함하고
있습니다. 둘 다 같은 큐 루트(`<프로젝트>/.dira`)만 보고 있으면 서로의 존재를 몰라도 한
프로젝트를 같이 운영합니다.

다음은 [첫 프로젝트 만들기](/docs/first-ticket)입니다.
