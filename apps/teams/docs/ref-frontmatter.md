# frontmatter 필드

사람이 쓰는 필드와 디스패처·엔진이 쓰는 필드는 갈립니다([티켓이 지나는 상태](/docs/states)가
이미 그 경계를 세웠습니다). 사람이 쓰는 필드에 엔진 쪽 값을 미리 채워 넣으면 안 됩니다.
`session_id:`를 채워두면 이미 할당된 티켓으로 보이고, 그러면 어떤 워커도 그 티켓을
집어 가지 않습니다.

## 사람이 쓰는 필드

| 필드 | 필수 | 뜻 |
|---|---|---|
| `ticket` | ✓ | 해시. 파일명과 같게 둡니다(없으면 파일명에서 땁니다) |
| `title` | ✓ | 사람이 읽는 제목 |
| `kind` | | `work`=지시 / `request`=부탁 / `feedback`=결과보고 / `answer`=답변 파일. 표시용이고 값을 강제하지 않습니다 |
| `persona` | | 수행할 페르소나 이름. 없으면 페르소나 없는 평범한 에이전트가 처리합니다. 알파벳·숫자·`-`·`_`만 통과합니다 |
| `squad` | | 수행할 스쿼드 이름 **하나**. `deps`와 달리 목록(`[...]`)이 아닙니다. 엔진이 이 값을 풀어 그 묶음의 리더를 띄우고 `persona`를 그 이름으로 덮어쓰기 때문에 `persona`와 같이 적지 않습니다([스쿼드](/docs/squads)) |
| `deps` | | `[<hash>...]` 하드 선후. 전부 완료여야 큐에 뜹니다 |
| `priority` | | `1`~`5`. 없거나 못 읽거나 범위 밖이면 `3`으로 읽습니다. 높은 쪽이 먼저 뽑히고, 높은 티켓이 기다리는 선행은 그 값을 물려받습니다 |
| `duedate` | | ISO 8601 시각(`2026-08-14T18:00:00+09:00`. 오프셋을 빼면 로컬 시각). 남은 시간이 5시간 이하면(이미 지난 것 포함) `5`로, 자기 `duedate`가 있고 7일 이상 남았으면 `1`로 읽습니다. 그 사이는 적힌 `priority`가 그대로 섭니다 |
| `req` | | 요구에서 쪼개져 나온 티켓이 적는 원본 요구의 해시. 순서가 아니라 출처라서 `deps`와 다릅니다 |
| `epic` | | 이 티켓이 드는 묶음의 번호 **하나**(`P273`). `deps`와 달리 목록(`[...]`)이 아니고 값을 파싱하지도 않습니다. 엔진은 안 보고 화면만 갈립니다([에픽](/docs/epics)) |
| `archives` | | 아카이브 티켓이 적는 대상 티켓 해시 **하나**. `deps`와 달리 목록(`[...]`)이 아닙니다. 이 값이 있으면 보드에 독립 카드로 서지 않고 대상 티켓에 겹쳐 붙습니다 |
| `continued` | | 다 못 끝낸 세션이 남은 범위를 넘긴 후속 티켓의 해시 **하나**. `archives`와 같이 목록(`[...]`)이 아닙니다. 이 값이 있으면 완료 배지가 `완료(이어짐)`으로 갈리고 그 후속으로 가는 링크가 됩니다([티켓이 지나는 상태](/docs/states)) |
| `handoffs` | | 이어받기 티켓이 자기가 몇 번째인지 적는 숫자. 앞 티켓 값에 1을 더해 씁니다. 키가 없으면 0으로 읽으니 첫 이어받기가 `1`입니다. 이 값이 `3`을 넘으면, 그러니까 네 번째 이어받기부터는 엔진이 잡자마자 도로 놓고 답변 대기로 잠급니다([티켓이 지나는 상태](/docs/states)) |

## 디스패처·엔진이 쓰는 필드

| 필드 | 쓰는 시점 | 뜻 |
|---|---|---|
| `session_id` | `assign` — 엔진을 띄우기 **전** | 있으면 할당된 것으로 보고 큐에서 제외합니다. 판정이 보는 값은 이것 하나뿐입니다 |
| `assigned_at` | `assign`과 동시 | 할당 시각(reap의 유예 판정에 쓰입니다) |
| `owner` | `assign`(자동 디스패치) 또는 `handclaim`(손 클레임) | 자동이면 `<페르소나 또는 agent> / <워커>-<sid 앞8자리>`, 손 클레임이면 호출자가 준 식별자 |
| `pid` | `setpid` — 엔진을 백그라운드로 띄운 **뒤**, 또는 `handclaim`이 조상 `claude` pid를 기록 | 생존 확인용. 큐 제외 판정과는 상관이 없습니다 |
| `inbox` | `setinbox` — 최초 프롬프트 주입이 끝난 **뒤** | 참견 FIFO 경로. FIFO 파일은 세션이 끝나면 사라지지만 이 값 자체는 정상 완료나 자동 스테일 회수로는 안 지워집니다. `unassign`이나 디스패치 실패로만 비워집니다 |
| `claimed_at` | `handclaim` | 손으로 잡은 시각(유휴 판정 유예에 쓰입니다) |
| `transcript` | `handclaim` | 그 순간 가장 최근 트랜스크립트 경로(유휴 판정용) |
| `attempts` | `reap`(회수할 때마다 증가) | 자동 회수 2회까지 세고, 답변 요청으로 전환되면 `0`으로 리셋됩니다. 티켓 상세 오른쪽 맨 위의 `다시 할당` 줄과는 [세는 사건이 다릅니다](/docs/screens) |
| `awaiting` | `reap`이 답변 요청으로 올릴 때(자동 회수 3회째, 또는 본문 마지막 절이 `## 블록`이면 횟수 무관 즉시), 그리고 사람이 `unassign --force`로 세션을 끊을 때 | 존재하지 않는 해시. 같은 값이 `deps`에도 같이 들어가고, 큐를 잠그는 것은 그 `deps` 쪽입니다. 같은 이름의 답변 파일(`<awaiting>.done.md`)이 생기면 저절로 풀립니다 |

`awaiting`은 세션도 씁니다. 요구를 쪼개던 세션이 추측 없이 더 못 갈 때 이 값을 직접
적습니다. 답이 도착한 뒤에도 지우지 않습니다. 기록으로 남고, 아직 기다리는 중인지는 답변
파일이 있는지로 판단합니다.

## 표 밖의 규칙 셋

`priority`에 `5`를 쓰는 것은 사람의 판단입니다. 그 값은 이미 도는 티켓을 밀어내기 때문에
세션은 `1`~`4`까지만 씁니다.

`duedate`는 `priority`를 고쳐 쓰지 않습니다. 티켓을 뽑을 때 시계를 한 번 보고 그 자리에서만
높이거나 낮춥니다. 파일에 적힌 숫자는 그대로 남습니다.

`kind: answer`는 태어날 때부터 완료 상태입니다(`<awaiting>.done.md`). 사람이나 앱이 만듭니다.
세션은 이 파일을 만들지 않습니다. 열린 채로 태어나면 페르소나 없는 티켓으로 아무 워커에게나
디스패치될 텐데, 이 파일은 아무도 수행하지 않기 때문입니다.
