# 페르소나와 프로토콜

## 페르소나 — 누가

`personas/<이름>/PROFILE.md`는 그 역할이 무엇을 판단 기준으로 삼는지 적은 파일이다.
형식이 없다 — 그냥 마크다운이다. 티켓의 `persona:` 값으로 이 이름을 찾아 프로필 본문을
프롬프트 머리에 그대로 인라인한다.

**티켓이 페르소나를 고른다.** 워커나 프로젝트가 아니라 티켓 하나하나의 `persona:` 값이
그 세션이 어떤 프로필을 쓸지 정한다. 같은 큐, 같은 워커라도 티켓마다 다른 페르소나로 돈다.

`persona:`가 없으면 페르소나 없이 디스패치되고, 그게 정상 경로다 — 롤플레잉이 필요한
티켓에만 붙인다. 이름은 적었는데 프로필 파일이 없으면 경고만 남고 그냥 돈다.

## 프로토콜 — 어떻게 같이 일하는가

`protocols/AGENTS.md`는 페르소나와 달리 **전원 공통**이다. 티켓이 고르지 않는다 — 있으면
모든 세션의 프롬프트에 인라인된다. 큐를 다루는 규약(티켓 성격별 처리, 핸드오프, 막혔을 때
대응)을 적는 자리다.

디렉터리인 이유는 `AGENTS.md`가 목차 역할을 하기 때문이다. 길어지는 세부 규약(예: 티켓
작성법을 담은 `tickets.md`)은 옆 파일로 빼고 `AGENTS.md`에서 가리키면, 세션이 필요할 때만
그 파일을 읽는다 — 프롬프트 전체에 싣지 않는다.

프롬프트 조립 순서는 **페르소나 → 프로토콜 → 티켓 지시 → 참조 컨텍스트**다. `dryrun`으로
실제 조립 결과를 그대로 볼 수 있다([첫 티켓 굴리기](/docs/first-ticket) 참고).

## 템플릿 — 출발점이지 엔진의 일부가 아니다

```
templates/
  protocols/AGENTS.md              큐를 다루는 규약. 전원 프롬프트에 실린다
  protocols/tickets.md             티켓 파일 작성법. AGENTS.md가 가리키고 필요할 때 읽힌다
  personas/pm/PROFILE.md           무엇을 만들지 정하고 쪼개서 티켓으로 내보낸다
  personas/developer/PROFILE.md    티켓을 돌아가는 코드로 바꾸고 증거를 남긴다
  personas/qa/PROFILE.md           "됐다"는 주장을 돌려보고 깬다
  personas/designer/PROFILE.md     화면을 확정한다. UI가 있는 프로젝트에서만 둔다
```

```bash
cp -r ~/Projects/dira/templates/* ~/Projects/myproject/.dira/
```

**엔진은 이게 없어도 그대로 돈다.** `personas/`도 `protocols/`도 없으면 페르소나 없는
평범한 에이전트가 티켓을 처리할 뿐이다 — 엔진이 이 디렉터리를 요구하지 않는다. 템플릿은
빈 파일에서 시작하지 않게 주는 출발점일 뿐이다.

복사한 순간부터 프로젝트의 것이다. 업스트림과 동기화되지 않는다 — 템플릿이 나중에 바뀌어도
복사본은 그대로다(엔진이 템플릿을 다시 찾아가지 않으니 그럴 방법도 없다). 프로젝트 이름·
경로·금지사항은 복사 직후 손으로 채운다.

다음은 [트러블슈팅](/docs/troubleshooting)이다.
