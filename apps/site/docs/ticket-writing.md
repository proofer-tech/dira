# 티켓 쓰는 법

티켓은 마크다운 파일 하나다. 특별한 형식이 없다고 [dira가 뭔가](/docs/what-is-dira)에서
이미 봤다 — 여기서는 그 안에 실제로 뭘 적는지를 본다.

```bash
H=$(python3 -c 'import uuid;print(uuid.uuid4().hex[:8])')
cat > ".dira/tickets/$H.md" <<EOF
---
ticket: $H
title: 한 줄 제목 — 무엇을 하는지
kind: work
persona: developer
deps: [3a7e10cd]
---

## Goal
왜 필요한지 + 무엇을 만드는지. 2~4줄.

## Done when
- [ ] 검증 가능한 문장
- [ ] 검증 가능한 문장
EOF
```

해시는 `$RANDOM`이나 직접 타이핑으로 만들지 않는다. 충돌하면 `find`가 엉뚱한 티켓을 준다 —
위처럼 `uuid`로 뽑는다.

## `kind` 세 가지

- **`work`** — 지시. 받은 페르소나가 수행하고 끝나면 완료로 넘어간다.
- **`request`** — 부탁·질문. 받은 사람은 답을 원본에 덧붙이지 않고 **새 `kind: feedback`
  티켓**으로 만든다. 원본은 질문의 기록으로 그대로 남는다.
- **`feedback`** — 결과보고·지적. 받은 사람이 조치가 필요하면 새 티켓을 만들고, 아니면 그냥
  끝낸다.

`kind`는 표시용이고 엔진이 값을 강제하지 않는다. 그래도 다음에 이 티켓을 읽는 사람(또는
페르소나)이 성격을 파악하는 유일한 단서라 비워두지 않는다.

## `Goal`과 `Done when`

`Goal`은 왜 필요한지와 무엇을 만드는지를 2~4줄로 적는다. 배경 설명이 아니라 세션이 시작하기
전에 읽고 판단할 근거다.

`Done when`은 체크박스로, 검증 가능한 문장을 적는다. "잘 되게 한다"가 아니라 "~하면 통과"로
써야 세션 자신이든 나중의 QA든 판정할 수 있다. 여섯 개를 넘으면 쪼갤 신호다 — 티켓 하나는
한 세션(5~25분)이 리뷰 가능한 변경 하나여야 한다. 화면 3개와 그 테스트가 필요하면 그건
티켓 하나가 아니라 넷이다.

## `deps`로 순서 만들기

`deps: [<해시>...]`에 적은 티켓 전부가 완료(다음 장 [상태는 파일명](/docs/states) 참고)여야
이 티켓이 큐에 뜬다. 하나라도 안 끝났으면 보드에서 `deps 대기`로 보이고 어떤 워커도 집어가지
않는다.

오타 난 해시를 적으면 그 티켓을 못 찾아 보수적으로 "미완료"로 판정하고 — 존재하지 않는
선행을 영원히 기다리는 셈이라 그 티켓은 영구 대기한다. 적기 전에 존재를 확인한다:

```bash
python3 tickets.py find .dira <해시>
```

병렬로 돌 수 있는 일에는 `deps`를 걸지 않는다. 걸지 않아도 되는 곳에 걸면 워커가 놀고 큐가
직렬화된다.

## 페르소나 지정

`persona:`에 이름을 적으면 그 이름의 `personas/<이름>/PROFILE.md` 본문이 프롬프트 머리에
그대로 인라인된다. `persona:`가 없으면 페르소나 없이 디스패치되고, 그게 정상 경로다 —
롤플레잉이 필요한 티켓에만 붙인다. 이름은 있는데 프로필 파일이 없으면 경고만 남고 그냥 돈다.

값은 경로 조각으로 쓰이므로 알파벳·숫자·`-`·`_`만 통과한다 — `persona: ../../.ssh` 같은
값으로 임의 파일이 프롬프트에 실려 나가지 않게 막는 장치다.

## 좋은 티켓과 나쁜 티켓

좋은 예:

```markdown
---
ticket: 9c4f21ab
title: 주문 목록에 CSV 내보내기 버튼 추가
kind: work
persona: developer
deps: [3a7e10cd]
---

## Goal
주문 목록 화면(`/orders`)에서 지금 화면에 보이는 필터 결과를 CSV로 내려받게 한다.
정산팀이 매주 이 화면을 캡처해 수동으로 옮기고 있다.

## Done when
- [ ] `/orders`에 "CSV 내보내기" 버튼이 보인다
- [ ] 누르면 현재 필터가 적용된 행만 CSV로 떨어진다
- [ ] 헤더 행에 컬럼명이 한글로 나온다
```

나쁜 예:

```markdown
---
ticket: a1
title: 주문 화면 개선
---

주문 화면이 좀 불편해서 손 봐주셨으면 합니다. CSV도 되면 좋을 것 같고
필터도 개선되면 좋겠어요.
```

무엇이 문제인가:

- `ticket: a1`이 8자 hex가 아니다 — 파일명과 어긋나면 조회 자체가 안 된다.
- `kind`가 없어 이게 지시인지 부탁인지 알 길이 없다.
- `Goal`도 `Done when`도 없다 — "좀 불편해서"가 그대로 지시가 되고, 세션이 무엇을 하면
  끝인지 판단할 근거가 없다.
- "CSV도 되면 좋을 것 같고 필터도"에 두 가지 이상이 뭉쳐 있다 — 화면 하나, 검증 하나가
  아니라 두 개 이상의 변경이라 쪼개야 한다.
