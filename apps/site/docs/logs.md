# 로그 읽는 법

로그는 셋이다. 무엇이 궁금한지에 따라 여는 파일이 다르다.

```
<루트>/workers/runner.log                        디스패치 기록
<루트>/workers/logs/<시각>-<워커>-<해시>.log      세션별 실제 출력
<루트>/workers/cron.log                          cron 자체의 리다이렉트
```

## `runner.log` — 디스패치가 무엇을 했는지

워커가 매 tick마다 자신이 한 일을 한 줄씩 적는다. 형식은 `<시각> [<워커이름>] <메시지>`다.
메시지는 접두어로 갈린다:

| 접두어 | 언제 | 뜻 |
|---|---|---|
| `DISPATCH` | 티켓을 잡아 세션을 띄운 순간 | `kind`·`persona`·`sid`·세션 로그 파일명을 같이 적는다 |
| `DONE` | 세션이 정상 종료 | 실제 `session_id`를 적는다 |
| `FAIL` | 세션이 오류로 끝남 | rc≠0 또는 응답의 `is_error` |
| `TIMEOUT` | `TICKET_MAXRUN` 초과로 강제종료 | rc가 143/137일 때 |
| `STALL` | 엔진이 최초 프롬프트를 못 받음 | `TICKET_FEED_TIMEOUT` 초과 |
| `NOTE` | 세션키 정정 | 응답의 실제 `session_id`가 사전 발급값과 다를 때 |
| `SKIP` | 이번 tick을 건너뜀 | 같은 워커가 앞 세션을 아직 쥐고 있을 때 |
| `WARN` | 정지시키지 않는 이상 상황 | 스테일 락 회수·컨텍스트 경로 없음·페르소나 프로필 없음 등 |
| `ERROR` | 선정·할당 자체가 실패 | `select`/`assign`이 실패했을 때 |
| `REAP` / `REAP-FAIL` | 스테일 티켓을 백로그로 회수(또는 회수 실패) | 매 tick 맨 앞 |
| `ASK` | 자동 회수 3회째 — 답변 요청으로 전환 | 본문에 `## 질문 n`이 붙는다 |
| `SUSPECT` | 손 클레임 세션이 유휴로 의심됨(보고만) | 자동 회수하지 않는다 |
| `UNASSIGN` / `UNASSIGN-DENY` | 할당 해제 성공(또는 산 세션이라 거부) | `unassign` 명령 |
| `AUTH 대기` | 헤드리스 토큰 없음 | 최초 1회만 남긴다 |

**"아무 일도 안 일어나는 것 같다"의 첫 확인 자리가 여기다.** `DISPATCH`가 안 찍히면
디스패치 자체가 안 된 것이고(선정 실패·인증 대기 등), `DISPATCH` 뒤에 `DONE`도
`FAIL`도 없으면 세션이 아직 도는 중이다.

## `logs/<시각>-<워커>-<해시>.log` — 세션이 실제로 무엇을 했는지

`runner.log`가 "언제 어떤 티켓을 물었나"라면 이 파일은 "그 세션 안에서 무슨 일이
있었나"다. 엔진의 표준에러와 최종 표준출력이 여기 쌓인다. 기본 엔진(`claude -p`,
스트리밍 입력)에서는 JSONL 한 줄이 곧 한 이벤트고, 마지막 `"type":"result"` 줄이
그 세션의 최종 판정이다(`FAIL`/`DONE` 판정의 근거).

`FAIL`이나 `TIMEOUT`이 `runner.log`에 찍혔을 때 **왜** 실패했는지는 이 파일에서만
보인다 — `runner.log`는 판정 결과만 적고, 세션이 실제로 무엇을 읽고 무엇을 시도하다
막혔는지는 여기 담긴다.

## `cron.log` — 워커 스크립트 자체가 깨졌을 때만 채워진다

crontab 줄이 리다이렉트하는 대상이다(`>> .../cron.log 2>&1`). 여기 쌓이는 것은
워커 **셸 스크립트 자체**의 표준출력·표준에러이지 세션의 출력이 아니다. 정상
동작 중에는 대개 비어 있다 — `tick.sh`가 하는 일은 전부 `runner.log`에 따로 적기
때문이다. 이 파일에 뭔가 있다면 `bash` 자체가 실행되지 못했거나(권한, 셔뱅 오류)
`tick.sh`가 시작하기도 전에 죽은 것이다.

## 어디부터 보나

1. **아무 일도 안 일어난 것 같다** → `runner.log`부터. `DISPATCH`가 있는지, 있다면
   그 뒤에 `DONE`/`FAIL`/`TIMEOUT`이 붙었는지 본다.
2. **`runner.log`조차 갱신되지 않는다** → `cron.log`를 본다. 워커 자체가 안 뜬 것이다
   (마운트 문제는 [트러블슈팅](/docs/troubleshooting) §워커가 아예 안 뜬다 참고).
3. **`FAIL`/`TIMEOUT`은 찍혔는데 이유를 알아야 한다** → 그 줄의 `log=` 파일명으로
   `logs/`의 세션별 로그를 연다.
