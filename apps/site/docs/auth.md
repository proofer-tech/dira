# 헤드리스 인증

**cron으로 돌릴 때만 필요하다.** 앱만 쓰거나 워커를 손으로만 부른다면(`dryrun`,
[첫 티켓 굴리기](/docs/first-ticket)에서 한 것처럼) 이 장은 건너뛰어도 된다.
cron이 사람 없이 워커를 깨우기 시작하는 순간부터 막히는 자리가 둘 생긴다 —
로그인 키체인과 macOS 파일·시스템 권한이다.

## 장기 인증 토큰

cron은 로그인 키체인에 접근하지 못한다. 화면 앞에 사람이 없는 상태로 도는 게
cron의 요지이기 때문이다. 그래서 cron으로 돌릴 워커에는 키체인 대신 쓸 장기
인증 토큰이 하나 필요하다.

```bash
mkdir -p ~/.config/dira
claude setup-token
printf %s '<토큰>' > ~/.config/dira/oauth-token && chmod 600 ~/.config/dira/oauth-token
```

`claude setup-token`이 낸 토큰을 `~/.config/dira/oauth-token`에 그대로 적는다.
`chmod 600`으로 소유자만 읽게 잠근다.

**토큰은 머신 로컬에 하나만 둔다.** 티켓 루트가 공유 드라이브에 있어도
`~/.config/dira`는 동기되지 않는 이 머신만의 자리다 — 큐를 옮기거나 공유해도
비밀이 같이 퍼지지 않는 이유가 이것이다. 워커를 여러 머신에서 돌리면 머신마다
따로 `setup-token`을 받는다.

## 전체 디스크 접근 권한

티켓 루트가 클라우드 마운트(구글드라이브 등)일 때 필수다. macOS는 cron이
띄우는 프로세스가 보호된 위치의 파일을 읽으려 하면 에러도 없이 조용히 막는다
— 파일이 없는 것처럼 보인다.

`설정 › 개인정보 보호 및 보안 › 전체 디스크 접근 권한`을 연다. 목록에 `cron`
자체는 뜨지 않으므로 `+`를 누른 뒤 `Cmd+Shift+G`로 `/usr/sbin/cron`을 직접
입력해 추가한다 — 실제로 파일을 읽는 건 워커 스크립트가 아니라 그걸 띄우는
cron 데몬이다. 켠 뒤에는 이미 등록해 둔 cron 작업이 있어도 곧바로 반영되지
않을 수 있으니, 한 번 손으로 워커를 불러 큐가 제대로 보이는지 확인한다.

## 워커를 새로 등록할 때마다 다시 묻는 승인

macOS는 crontab에 새 줄을 쓰는 시도마다 `앱 관리` 권한이 있는지 확인한다.
없으면 시스템 창을 띄우고 사람의 응답을 기다린다 — 응답 전까지 그 등록은
멈춰 있다. `허용`을 누르면 그 시도는 끝까지 간다.

문제는 **이 승인이 다음 등록까지 남지 않는다는 것**이다. 워커를 하나 더 만들
때마다(다음 장 [동시성](/docs/concurrency)) 같은 창이 또 뜬다 — 한 번 눌렀다고
다시 안 물을 거라 기대하지 않는다. 미리 켜두거나 확인하는 자리는 `설정 ›
개인정보 보호 및 보안 › 앱 관리`다.

다음은 [동시성](/docs/concurrency)이다.
