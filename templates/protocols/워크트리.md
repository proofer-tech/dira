# 워크트리 - 배치와 심링크 (워커를 2개 이상 돌릴 때)

인라인 `AGENTS.md` §당신이 있는 곳에서 내려온 세부다. 워커를 하나만 돌린다면 이 파일이
필요 없다 - 레포에서 그냥 일하면 된다.

## 배치

워커가 여럿이면 cwd는 `<프로젝트>/.dira/worktrees/<워커>`이고 레포의 **git 워크트리**다
(브랜치 `wt/<워커>`). 워커마다 자기 워크트리가 있어서 동시에 도는 두 세션이 같은 파일을
밟지 않는다. 큐 루트 하나가 그 큐의 워커-티켓-작업 트리를 전부 담으므로, 큐를 옮기는 것이
곧 전부를 옮기는 것이다.

| 여기 있는 것 | 성격 |
|---|---|
| 프로젝트 소스-문서 | 워크트리의 **자기 사본**. 여기서 고치고 커밋한다 |
| `.dira/` | **심링크 -> canonical 큐 1개.** gitignore돼 있어 커밋 대상이 아니다 |

큐 사본은 세상에 하나뿐이다(`<프로젝트>/.dira`). 심링크 덕에 상대경로 `.dira/tickets/...`가
그냥 통한다. `git status`에 티켓이 안 뜨는 건 정상이다.

## 사람이 트리를 만들 때 - 3줄, 마지막 줄은 장식이 아니다

**심링크는 상대경로 `../..`다** - 이 배치에서 큐는 워크트리의 조부모다.

```
git -C <프로젝트> worktree add <프로젝트>/.dira/worktrees/<워커> -b wt/<워커>
ln -s ../.. <프로젝트>/.dira/worktrees/<워커>/.dira
ls -ld <프로젝트>/.dira/worktrees/<워커>/.dira    # `l`로 시작해야 한다
```

`ln -s`는 대상이 **이미 있으면 그 안쪽에** 링크를 만든다 - `.dira/.dira`가 생기고 세션은
미끼 큐를 본다. 검증 줄이 `d`로 시작하면 그 일이 일어난 것이다.

## 이 배치의 천장

`.dira`가 워크트리 안을 가리키므로 `worktrees/<워커>/.dira/worktrees/...`로 재귀한다. 기본
설정의 도구는 심링크를 안 따라가지만 **워크트리 루트에서 `find -L`-`grep -R`을 돌리지
않는다.**

## 받는 트리에서 커밋한 예외 - `Exception:` 한 줄

세션이 일하는 자리는 자기 워크트리이고, 받는 트리(통합 브랜치가 체크아웃된 그 트리)에서
커밋을 내는 것은 예외다. 예외가 실제로 필요했으면 **숨기지 말고 표기한다.**

- **형식**은 커밋 메시지의 `Exception: <사유>` 한 줄이고, 자리는 `Ticket:` 줄과 같은 꼬리
  문단이다.
- **적는 손**은 `bash .dira/push.sh ship <해시> "<제목>" "<본문>"`의 `<본문>` 마지막 줄이다.
  **`ship`에 새 플래그를 만들지 않는다** - 만들면 예외를 내는 경로가 두 벌이 된다.
- **사유**는 *왜 워크트리에서 할 수 없었나* 한 문장이다. `긴급`이나 `임시`는 이유를 담고 있지
  않으므로 사유가 아니다.
- **사람이 직접 내는 커밋은 대상이 아니다.** 판정은 `Ticket:` 트레일러의 유무 하나이고, 사람이
  손으로 낸 커밋에는 그 줄이 없어서 애초에 후보로 잡히지 않는다.
- **커밋 메시지에만 남기는 것은 금지다** - `## 결과`에 그 커밋 해시와 사유를 같이 적는다.
  메시지에만 두면 티켓을 읽는 사람이 그 사실을 못 본다.

`push.sh`에 `drift` 서브커맨드가 있는 프로젝트에서는 표기를 뺀 세션 커밋을 그 명령이 한 줄씩
센다. 세기만 하고 막지도 되돌리지도 않으므로, 표기를 빠뜨려도 경고 없이 그 목록에 남는다.

## 커밋이 졌을 때 - 어느 트리에서 졌나로 갈린다

`git rebase`도 push도 아닌 `git commit` 자체가 실패한 자리다. 갈래는 둘이고, 가르는 한 줄은
`git rev-parse --git-common-dir`다 - `.git` 하나로 나오면 받는 트리에 있는 것이고,
워크트리에서는 절대경로가 나온다.

**(1) 받는 트리에서 졌으면 원상복구가 먼저다.** 순서는 셋이고 뒤집지 않는다.

```
git diff <파일> > /tmp/<티켓 해시>.patch     # 내 편집을 먼저 뜬다
git restore <파일>                           # 받는 트리를 원래대로
cd <내 워크트리> && git rebase <통합 브랜치> && git apply /tmp/<티켓 해시>.patch
```

**diff를 뜨기 전에 지우는 것은 금지다** - 위 세 줄을 순서대로 돌리고, 복구한 사실과 그 커밋을
시도한 자리를 `## 결과`에 적는다. `git reset --hard`도 `git stash`도 안 쓴다 - 그 트리에 사람의
미커밋 편집이 같이 있을 수 있고 stash 스택은 워크트리 전부가 나눠 쓴다.

**(2) 자기 워크트리에서 졌으면 첫 실패에 `## 블록`이다.** push의 3회 규칙을 여기로 가져오지
않는다 - push가 셋을 허용하는 이유는 다른 워커와의 경쟁이고, 커밋에는 그 경쟁이 없어서 재시도가
같은 자리에서 같은 오류를 낸다. **두 번째 `git commit`을 시도하는 것이 금지이고**, 대신 그
자리에서 `## 블록`을 쓰며, `git commit`의 stderr를 거기 그대로 붙인다.

두 갈래 다 통합 브랜치에 흔적을 안 남긴다 - (1)은 남은 흔적을 걷고, (2)는 자기 브랜치 위에서
지므로 남길 흔적이 없다.

## 시작에 만난 미커밋 변경

디스패치받은 세션이 `git rebase master`를 돌렸는데 자기 워크트리에 남의 미커밋 변경이 있어
막히는 경우가 있다. 그 자리에서 순서는 이렇다.

1. 받은 티켓에 `## 결과`-`## 블록`이 이미 붙어 있으면 재디스패치다 - 이 절이 아니라
   `재디스패치-복구.md`로 간다.
2. 변경된 파일 이름으로 티켓 큐를 grep해 주인 티켓을 찾는다.
3. 주인 티켓이 미완이거나 아직 배정되지 않았으면 **버린다** - `git restore .`과 미추적 파일
   삭제. 그 티켓은 다시 디스패치되고 그 세션이 처음부터 다시 쓴다.
4. 주인 티켓이 완료됐는데 그 산출물이 받는 트리에 없거나, 주인을 못 찾으면 **보존한다** -
   `git tag orphan/<워커>/<UTC 초> $(git stash create)`를 돌리고 `git restore .`.
5. 보존했으면 **후속 티켓 한 장**을 낸다. 담당은 주인 티켓과 같은 사람-역할로 하고, 본문에
   태그 이름과 `git show --stat <태그>`를 적는다. 티켓 없이 보존한 것은 보존이 아니다.

금지 셋 - `git stash push`(스택이 워크트리 전부와 공유라 동시에 도는 세션이 남의 것을
pop한다), 받는 트리에 WIP 커밋(워커 전부가 다음 rebase에서 검토 안 된 절반을 받는다), 큐
밖의 임시 파일(어디에도 등록 안 되면 아무도 못 찾는다). 손해는 보관이 아니라 포인터다 - 잃는
것은 산출물 자체가 아니라 **그 산출물이 있다는 사실을 아는 자리**다.
