# 세션이 끝나는 자리 - 턴을 닫을 때와 미완으로 넘길 때

인라인 `AGENTS.md` §턴을 닫으면 세션이 끝난다 - §미완으로 끝날 때에서 내려온 세부다.

## 턴을 닫으면 세션이 끝난다 - 알림을 기다리는 자리가 없다

엔진의 감시 루프가 마지막 줄이 `result`인지 보고 그 자리에서 세션을 끝낸다 - MAXRUN은 그 줄이
영영 안 오는 경우를 위한 것이지, 세션이 스스로 끝을 미루는 자리가 아니다. 백그라운드로 던진
작업(테스트-빌드 등)의 알림을 받을 창이 없다 - 알림이 와도 세션은 이미 없다.

- 백그라운드로 띄웠으면 결과를 **같은 턴 안에서** 받는다. 전경에서 돌리거나, 길면 폴링을
  계속한다 - 던지고 턴을 닫지 않는다.
- **`## 진행 계획`을 든 티켓이 특히 위험하다.** 계획 단위로 끊어 일하는 모양이 "이 단계는
  백그라운드에 걸고 다음으로 넘어간다"는 오해와 붙기 쉽다.

## 미완으로 끝날 때 - 다섯 줄 순서

`## Done when` 박스를 다 못 채웠는데 이번 턴으로 끝내야 한다고 판단했으면 - **판단 주체는
세션 자신이다** - 죽지 말고 넘긴다. **push가 맨 앞이다**(완료 트리거와 같은 이유 - 통합 안 된
작업이 완료로 기록되면 안 된다):

1. 여기까지 참인 `## Done when` 박스를 `- [x]`로 켜고 못 채운 것은 `- [ ]`로 둔다.
2. 이 프로젝트의 push 절차를 그대로 따른다(인라인 §git).
3. 이어받기 티켓 **한 장**을 발행한다(쪼개지 않는다).
4. 원본 프론트매터에 `continued: <새 해시>` 한 줄.
5. `## 결과`에 어디까지 왔는지 + `-> <새 해시> 남은 범위`를 적고, 아카이빙을 쓰는 프로젝트면
   완료 트리거대로 아카이브 티켓을 낸 뒤 `.done`으로 rename.

이어받기 티켓의 모양:

| 키 | 값 |
|---|---|
| `persona` | 원본과 같다. 남은 일은 남은 사람의 일이다 |
| `epic` `req` | 쓰고 있었다면 원본 값을 그대로 물려받는다 |
| `deps` | **안 건다.** 원본이 곧 `.done`이 되고 하드 선후가 아니다 |
| 본문 `## Goal` | 남은 범위. 원본 stem을 한 줄로 가리킨다 |
| 본문 `## Done when` | 원본에서 못 채운 박스를 그대로 옮긴다 |

- **`## 진행 계획`을 들고 있었으면 남은 계획 줄이 그대로 이어받기 티켓의 계획이 된다.**
- **`## 블록`이 아니다.** 사람이 답할 것이 없다 - 남은 일이 무엇인지는 세션이 안다. CORE의
  When blocked 목록에 있는 "won't fit one session (propose a split, stop)" 한 줄을 이 절이
  이 자리에서 **대체한다** - 이미 일부가 통합된 뒤라면 멈춰 서서 사람을 부르는 것보다 남은
  것을 한 장으로 넘기는 것이 싸다.
- **한도(`한도.md`)는 이 절이 아니다.** 가르는 질문 하나 - **지금 이 턴에 글을 쓸 수 있나.**
  쓸 수 있으면 이 절, 왕복이 이미 거절되고 있으면 한도다.
