# 협업 프로토콜

당신은 이 큐에서 티켓 하나를 받아 수행하는 에이전트다. 큐는 파일이고, 파일이 곧 상태다.
당신이 큐를 망가뜨리면 당신의 다음 티켓이 사라진다. 그 자각을 가지고 일한다.

이 문서는 **이 프로젝트의 관습**이다. 큐를 다루는 규약(코어)은 엔진이 매번 프롬프트 앞에
인라인하므로 여기 사본이 없다.

## 당신이 있는 곳 — git 워크트리 (워커를 2개 이상 돌릴 때)

워커를 하나만 돌린다면 이 절은 건너뛴다 — 레포에서 그냥 일하면 된다.

워커가 여럿이면 cwd는 `<프로젝트>/.dira/worktrees/<워커>`이고 레포의 **git 워크트리**다
(브랜치 `wt/<워커>`). 워커마다 자기 워크트리가 있어서 동시에 도는 두 세션이 같은 파일을 밟지 않는다.
큐 루트 하나가 그 큐의 워커·티켓·작업 트리를 전부 담으므로, 큐를 옮기는 것이 곧 전부를 옮기는 것이다.

| 여기 있는 것 | 성격 |
|---|---|
| 프로젝트 소스·문서 | 워크트리의 **자기 사본**. 여기서 고치고 커밋한다 |
| `.dira/` | **심링크 → canonical 큐 1개.** gitignore돼 있어 커밋 대상이 아니다 |

큐 사본은 세상에 하나뿐이다(`<프로젝트>/.dira`). 심링크 덕에 상대경로
`.dira/tickets/...`가 그냥 통한다. `git status`에 티켓이 안 뜨는 건 정상이다.

**심링크는 상대경로 `../..`다** — 이 배치에서 큐는 워크트리의 조부모다. 사람이 트리를 만들 때
쓰는 3줄이고, 마지막 줄은 장식이 아니다:

```
git -C <프로젝트> worktree add <프로젝트>/.dira/worktrees/<워커> -b wt/<워커>
ln -s ../.. <프로젝트>/.dira/worktrees/<워커>/.dira
ls -ld <프로젝트>/.dira/worktrees/<워커>/.dira    # `l`로 시작해야 한다
```

`ln -s`는 대상이 **이미 있으면 그 안쪽에** 링크를 만든다 — `.dira/.dira`가 생기고 세션은
미끼 큐를 본다. 검증 줄이 `d`로 시작하면 그 일이 일어난 것이다.

이 배치의 천장: `.dira`가 워크트리 안을 가리키므로 `worktrees/<워커>/.dira/worktrees/…`로
재귀한다. 기본 설정의 도구는 심링크를 안 따라가지만 **워크트리 루트에서 `find -L`·`grep -R`을
돌리지 않는다.**

## git — 시작 · 끝

`<통합 브랜치>`는 이 프로젝트가 통합에 쓰는 브랜치다(`master` 또는 `main`).

**시작하자마자**: `git rebase <통합 브랜치>`
다른 세션이 이미 올린 결과를 받는다. 건너뛰면 있어야 할 파일이 없다고 헛짚는다.

**받은 티켓에 `## 결과`나 `## 블록`이 이미 붙어 있으면 재디스패치다 — 그 글을 믿지 않는다.**
앞 세션이 `## 결과` 마지막 줄에 `커밋 + push 성공`까지 적어 놓고 **커밋을 하나도 안 한 채**
죽는 일이 있다. 그 절은 검증 출력이 아니라 **주장**이다. 적힌 커밋 해시를 세지 말고 **산출물이
통합 브랜치에 있는지 내용으로** 확인한다 — `git log --oneline <통합 브랜치> -- <파일>` 또는
`grep`. 있으면 그대로 이어서 하고, 없으면 처음부터 다시 쓰기 전에 아래를 본다.

**워커가 여럿이면 앞 세션의 작업이 다른 워커 트리에 커밋 안 된 채 남아 있다.** 재디스패치는
같은 워커로 온다는 보장이 없고 **앞 워커 이름은 티켓에 안 남는다**(디스패치가 `owner:`를 자기
워커로 덮어쓴다). 그래서 전부 훑는 것이 유일한 길이다:

```
$ for w in <프로젝트>/.dira/worktrees/*/; do \
    printf '%s: ' "$(basename "$w")"; git -C "$w" status --porcelain | wc -l; done
```

**`-uno`를 붙이지 않는다.** 앞 세션이 만든 것이 **새 파일**이면 `-uno`가 그것을 못 보고 `0`을
준다 — 깨끗하다고 읽고 산출물을 처음부터 다시 쓰게 된다.

- **더러운 트리가 나오면 산 세션이 쓰고 있는지 먼저 본다.** `grep -l '^owner: .* / <워커>-'
  .dira/tickets/*.wip.md` — 나오는 것이 있으면 그 트리는 **지금 도는 세션의 작업 트리**다.
  내 티켓 것이 아니라고 보고 **손대지 않는다**.
- 내 산출물이면 가져온다: `git -C <그 트리> diff HEAD > /tmp/<내 해시>.patch` → 내 트리에서
  `git apply`. **미추적 파일은 diff에 안 들어간다** — `git -C <그 트리> ls-files -o
  --exclude-standard`로 세어 보고 있으면 따로 복사한다.
- **가져온 뒤 그 트리를 정리한다** — `git -C <그 트리> restore .` + 복사한 미추적 파일 삭제.
  안 하면 그 워커의 다음 세션이 `git rebase <통합 브랜치>`에서 막혀 티켓 하나를 헛으로 태운다.
  (아래 §push가 거부될 때의 *남의 트리를 고치지 않는다*는 **받는 트리**(사람의 편집이 섞이는
  자리) 규약이다. 여기는 세션만 쓰는 워커 트리이고, 산 세션이 없다는 것을 방금 확인했다.)

**작업 중**: 자유롭게 커밋한다. 워크트리가 격리돼 있어 안전하다.
메시지는 한 줄 요약 + 본문, 마지막 줄에 `Ticket: <해시>`.

**끝나면**: `git push . HEAD:<통합 브랜치>`
**이게 다음 티켓이 당신 결과를 보는 유일한 길이다.** push하지 않으면 당신의 작업은 존재하지 않는다.

- 거부되면(non-fast-forward = 다른 세션이 먼저 올렸다) `git rebase <통합 브랜치>` 후 재시도.
- 충돌은 **자기 티켓 범위만** 해결한다. 남의 변경을 버려서 통과시키지 않는다.
- 3회 실패하면 `## 블록`으로 남기고 끝낸다.
- 금지: `push --force`, `reset --hard`, `stash`, 원격(origin) push. 사람이 한다.

**`Working directory has staged changes` / `... unstaged changes`로 거부되면 재시도하지 말고
즉시 `## 블록`이다.** 받는 트리(`<프로젝트>`, `<통합 브랜치>` 체크아웃)가 깨끗할 때만
`updateInstead`가 push를 받는다. 더러운 건 저쪽 트리라서 **rebase도 push 대상 변경도 통하지 않는다.**
조사하지 말고, 무엇이 걸려 있는지만 본다(**읽기 전용 — 저 트리를 고치지 않는다**):

```
$ git -C <프로젝트> status --porcelain -uno | wc -l   # 이 숫자가 근거다
$ git -C <프로젝트> diff --cached --stat              # 무엇이 걸려 있나
```

원인은 둘이고 **둘 다 `## 블록`**이다. 갈리는 건 종료 방법이 아니라 블록에 적을 내용이다:

- **사람의 커밋 안 된 변경.** 사람이 그 트리를 커밋할 때까지 아무 세션도 통합할 수 없다.
- **경쟁 push가 남긴 잔해.** `updateInstead`는 **작업 트리를 먼저 갱신하고 ref를 나중에** 잡는다.
  두 세션이 동시에 밀면 ref 경쟁에서 진 쪽(`incorrect old value provided`)은 ref를 못 얻지만
  그 트리는 이미 바뀐 뒤다 — 진 쪽 내용이 staged로 남아 다음 push를 **전부** 막는다.
  사람은 아무것도 안 했다. `diff --cached`가 **이미 통합 브랜치에 있는 커밋을 되돌리는 diff**면
  이것이다. 블록에 그렇게 적어라: "경쟁 push 잔해로 보인다 — `git -C <프로젝트> restore
  --staged --worktree <파일>`로 풀린다." **당신이 지우지 마라. 커밋도 하지 마라**(통합된 커밋을
  되돌린다). 남의 트리에서 되돌릴 수 없는 명령을 실행하는 건 사람이 한다.

이 잔해로 세션 여럿이 헛돌고 같은 커밋이 워크트리 2곳에 2벌 생긴 사고가 실제로 있었다.
디스패처가 앞에서 막을 수 있는 건 첫 번째 원인뿐이다 — 두 번째는 게이트를 통과한 뒤에 생기고
사람의 편집과 구분되지 않는다.

당신의 커밋은 브랜치에 남아 있으니 `## 블록`에 **브랜치와 커밋 해시**를 적어라. 사람이 그걸로 넣는다.
**끝냈으면 빨리 끝내라** — 이 벽이 서 있는 동안 어떤 워커도 결과를 통합하지 못한다.
당신이 남긴 한 줄이 사람이 그걸 몇 초 만에 푸는 유일한 단서다.

## 회고 예산 — 페르소나 `memory/` 합 150,000 B

`CORE.md` §회고가 도는 자리에서 같이 걸린다 — `## 결과`를 쓰기 직전에
`<프로젝트>/.dira/personas/<이름>/memory/`를 열 때다. 메모리는 디스패치 프롬프트에 통째로
실려서, 한 세션이 더한 한 절을 그 페르소나의 **이후 모든 세션**이 값으로 낸다. 세션 수만큼
자라는 축이라 개념 수를 묶는 §회고 2가 이것까지 막지는 못한다.

**예산은 페르소나 하나의 `memory/` 합 150,000 B다.** 줄 수가 아니라 바이트다.

```bash
cat "<프로젝트>/.dira/personas/<페르소나>/memory/"*.md | wc -c   # 150000 넘으면 아래가 걸린다
```

**파일 하나에 걸지 않는 이유는 그게 가르기로 통과하기 때문이다** — 큰 파일을 둘로 가르면
검사를 지나는데 가르기는 총 바이트를 되레 늘린다(제목·`관련:`·`출처:` 꼬리가 벌수만큼 는다).
합은 가르기로 안 움직이고, 화면 `자수`가 그리는 값도 이 합이다.

- **금지가 아니라 조건부 선행 작업이다.** 합이 넘는 것 자체는 위반이 아니다. 묶이는 것은
  **어떤 파일에 무언가를 더하는 순간**이다 — 그 페르소나가 예산 위에 있으면 **자기가 지금
  만지는 그 파일 하나**를 줄이고 더한다. **남의 파일을 열지 않는다.** 그래서 제일 뜨거운
  파일이 제일 먼저 줄고, 아무도 안 만지는 파일에는 아무 일도 안 일어난다.
- **한 번에 예산 아래로 내리라는 뜻이 아니다.** 초과가 크면 한 세션이 못 갚는다. 계약은
  *예산 아래로 내린다*가 아니라 **`그 세션이 더한 바이트보다 많이 줄인다`**이다 — 넘어 있는
  동안 합이 단조 감소하고, 예산 아래로 내려오면 이 문장이 저절로 꺼진다.
- **접는 것은 일화이고 남기는 것은 판정이다.** 규칙의 임계를 만드는 수는 계약이라 그대로 둔다.
  그 규칙이 나온 **경위**는 `출처:` 해시가 대신할 수 있다 — 무엇을 어떻게 알아냈는지 늘어놓은
  문단은 판정 한 줄 + 그 해시로 줄어든다. 그 줄이 형식에 처음부터 들어 있던 값이 여기서 갚인다.
- **접을 것이 없으면 줄이지 말고 그대로 더한다.** 같은 판정을 두 번 말하는 자리가 없는데
  큰 파일이 있다 — 명령과 출력이 길어서 큰 단일 개념이 그렇다. 억지로 접으면 다음
  세션이 그 명령을 다시 알아낸다. **`##` 절 수로 판정하지 않는다** — 페르소나마다 습관이 달라
  같은 성질의 파일이 한쪽은 절 아홉, 한쪽은 0개다.
- **가르는 것은 예산을 안 갚는다.** 엔진 글롭이 `memory/*.md`를 전부 싣기 때문에, 한 장을
  여러 장으로 갈라도 제목·`관련:`·`출처:` 꼬리가 늘어 총합은 오히려 커진다. 한 파일이 개념
  둘이면 §회고의 *개념 하나에 파일 하나*가 이겨서 가르는 것이 맞다. 다만 **가르는 것과 줄이는
  것은 다른 일이고 이 예산이 세는 것은 뒤쪽이다.**

## 완료 트리거 — 아카이브 티켓을 내고 끝낸다

아카이빙을 쓰는 프로젝트에서만 해당한다(`<프로젝트>/.dira/personas/archive-manager/`가 있으면 켜져 있다).

티켓을 끝낼 때 아카이브 티켓 하나를 발행한다. 자리는 **push가 성공한 다음 · 파일을 `.done`으로
rename하기 직전**이다. rename이 완료 신고라 그 뒤는 세션이 이미 없을 수 있고, push보다 앞이면
통합되지도 않은 작업의 아카이브 티켓이 남는다. 엔진이 rename을 지켜보지 않으므로 발행하는
주체는 언제나 끝내는 세션 자신이다.

```bash
H=$(python3 -c 'import uuid;print(uuid.uuid4().hex[:8])')
cat > "<프로젝트>/.dira/tickets/$H.md" <<EOF
---
ticket: $H
title: 아카이브 — <내 해시> <내 티켓 제목>
kind: work
persona: archive-manager
archives: <내 해시>
---

## Goal
<내 해시> 티켓 하나를 아카이빙한다.

## Done when
- [ ] 산출물이 archive-manager PROFILE의 자리 표대로 남는다
EOF
```

- 한 티켓이 가리키는 **대상 해시는 하나**다. 여러 건을 묶지 않는다.
- **`archives:`가 그 대상을 기계가 읽는 형태로 적는 자리다.** 값은 stem 하나이고 `deps:`처럼
  목록(`[...]`)으로 쓰지 않는다. 이 키를 읽는 화면이 있는 프로젝트에서는 아카이브 티켓이
  독립 카드 대신 대상 티켓에 붙어 선다 — 없으면 그냥 보통 티켓으로 보인다.
- **끝낸 티켓을 아카이브 매니저에게 넘겨주는 것이 아니다.** 발행하는 것은 새 티켓 하나뿐이고,
  방금 끝낸 티켓의 `persona:`는 손대지 않은 채 `.done`이 된다. 아카이브 세션이 대상 티켓에서
  하는 일은 본문 맨 아래 `## 아카이브` 절을 덧붙이는 것 하나다 — 상태를 되돌리거나 다시 잡거나
  앞 세션이 쓴 `## 결과`를 고치지 않는다.
- **아카이브 티켓은 아카이브 티켓을 내지 않는다.** 지금 끝내는 티켓의 `persona:`가
  `archive-manager`면 이 절을 건너뛰고 곧바로 rename한다 — 고리가 끊기는 자리가 여기뿐이다.
- 티켓 문법은 코어 `CORE-TICKETS.md`에 있다. 틀리면 조용히 큐에서 안 보인다.

## 브라우저를 띄울 때 (CDP)

에이전트가 브라우저를 띄우는 프로젝트에서만 해당한다.

사람이 이 화면 앞에서 다른 일을 하고 있다. **크롬이 앞으로 튀어나오면 그 사람의 작업을 끊는다.**

- 기본은 헤드리스다. 스크린샷·클릭·폼 입력·팝오버 전부 CDP로 되고 창이 아예 안 뜬다:
  `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --remote-debugging-port=<포트> --user-data-dir=/tmp/qa-<해시>/chrome-profile --window-size=1440,900 about:blank &`
- **사람의 로그인이 들어 있는 프로필에는 헤드리스를 붙이지 않는다.** 헤드리스는 키체인에 못 붙어
  쿠키를 복호화하지 못하고 **그 쿠키를 지운다** — 읽기가 아니라 파괴다. 한 번 지우면 사람이
  다시 로그인해야 한다(실측: 인증쿠키 18건 → 0건, 다음 로드가 로그인 화면).
  그런 프로필은 아래 `open -g`로 띄우고 CDP로 몬다.
- 눈으로 볼 창이 정말 필요하면 **`open -g`로 띄운다**(창은 뜨고 포커스는 안 넘어간다):
  `open -na "Google Chrome" -g --args --remote-debugging-port=<포트> --user-data-dir=/tmp/qa-<해시>/chrome-profile --no-first-run --no-default-browser-check about:blank`
  바이너리를 직접 실행하면 앱이 활성화돼 포커스를 뺏는다 — 창이 필요할 땐 `open -g`만 쓴다.
  창이 떠 있어도 `Page.navigate`·`Runtime.evaluate`·클릭은 전부 CDP로 된다.
- 포트는 세션마다 다르게(9222는 이미 다른 프로세스가 쓰고 있을 수 있다). `--user-data-dir`은 반드시
  전용 임시 경로 — 빼면 사람이 쓰는 크롬 창에 붙는다.
- **끝나면 죽인다.** 남긴 크롬은 다음 세션의 포트를 먹는다.
