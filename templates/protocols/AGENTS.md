# 협업 프로토콜

당신은 이 큐에서 티켓 하나를 받아 수행하는 에이전트다. 큐는 파일이고, 파일이 곧 상태다.
당신이 큐를 망가뜨리면 당신의 다음 티켓이 사라진다. 그 자각을 가지고 일한다.

이 문서는 **큐를 다루는 규약**이다. 무엇을 만들지는 티켓이, 어떻게 만들지는 프로젝트 문서가 정한다.

## 당신이 있는 곳 — git 워크트리 (워커를 2개 이상 돌릴 때)

워커를 하나만 돌린다면 이 절은 건너뛴다 — 레포에서 그냥 일하면 된다.

워커가 여럿이면 cwd는 `<프로젝트>-wt/<워커>`이고 레포의 **git 워크트리**다(브랜치 `wt/<워커>`).
워커마다 자기 워크트리가 있어서 동시에 도는 두 세션이 같은 파일을 밟지 않는다.

| 여기 있는 것 | 성격 |
|---|---|
| 프로젝트 소스·문서 | 워크트리의 **자기 사본**. 여기서 고치고 커밋한다 |
| `.fs-tickets/` | **심링크 → canonical 큐 1개.** gitignore돼 있어 커밋 대상이 아니다 |

큐 사본은 세상에 하나뿐이다(`<프로젝트>/.fs-tickets`). 심링크 덕에 상대경로
`.fs-tickets/tickets/...`가 그냥 통한다. `git status`에 티켓이 안 뜨는 건 정상이다.

## git — 시작 · 끝

`<통합 브랜치>`는 이 프로젝트가 통합에 쓰는 브랜치다(`master` 또는 `main`).

**시작하자마자**: `git rebase <통합 브랜치>`
다른 세션이 이미 올린 결과를 받는다. 건너뛰면 있어야 할 파일이 없다고 헛짚는다.

**작업 중**: 자유롭게 커밋한다. 워크트리가 격리돼 있어 안전하다.
메시지는 한 줄 요약 + 본문, 마지막 줄에 `Ticket: <해시>`.

**끝나면**: `git push . HEAD:<통합 브랜치>`
**이게 다음 티켓이 당신 결과를 보는 유일한 길이다.** push하지 않으면 당신의 작업은 존재하지 않는다.

- 거부되면(non-fast-forward = 다른 세션이 먼저 올렸다) `git rebase <통합 브랜치>` 후 재시도.
- 충돌은 **자기 티켓 범위만** 해결한다. 남의 변경을 버려서 통과시키지 않는다.
- 3회 실패하면 `## 블록`으로 남기고 끝낸다.
- 금지: `push --force`, `reset --hard`, `stash`, 원격(origin) push. 사람이 한다.

**`Working directory has staged changes` / `... unstaged changes`로 거부되면 재시도하지 말고
즉시 `## 블록`이다.** 받는 트리(`<프로젝트>`, `<통합 브랜치>` 체크아웃)가 깨끗할 때만
`updateInstead`가 push를 받는다. 더러운 건 저쪽 트리라서 **rebase도 push 대상 변경도 통하지 않는다.**
조사하지 말고, 무엇이 걸려 있는지만 본다(**읽기 전용 — 저 트리를 고치지 않는다**):

```
$ git -C <프로젝트> status --porcelain -uno | wc -l   # 이 숫자가 근거다
$ git -C <프로젝트> diff --cached --stat              # 무엇이 걸려 있나
```

원인은 둘이고 **둘 다 `## 블록`**이다. 갈리는 건 종료 방법이 아니라 블록에 적을 내용이다:

- **사람의 커밋 안 된 변경.** 사람이 그 트리를 커밋할 때까지 아무 세션도 통합할 수 없다.
- **경쟁 push가 남긴 잔해.** `updateInstead`는 **작업 트리를 먼저 갱신하고 ref를 나중에** 잡는다.
  두 세션이 동시에 밀면 ref 경쟁에서 진 쪽(`incorrect old value provided`)은 ref를 못 얻지만
  그 트리는 이미 바뀐 뒤다 — 진 쪽 내용이 staged로 남아 다음 push를 **전부** 막는다.
  사람은 아무것도 안 했다. `diff --cached`가 **이미 통합 브랜치에 있는 커밋을 되돌리는 diff**면
  이것이다. 블록에 그렇게 적어라: "경쟁 push 잔해로 보인다 — `git -C <프로젝트> restore
  --staged --worktree <파일>`로 풀린다." **당신이 지우지 마라. 커밋도 하지 마라**(통합된 커밋을
  되돌린다). 남의 트리에서 되돌릴 수 없는 명령을 실행하는 건 사람이 한다.

이 잔해로 세션 여럿이 헛돌고 같은 커밋이 워크트리 2곳에 2벌 생긴 사고가 실제로 있었다.
디스패처가 앞에서 막을 수 있는 건 첫 번째 원인뿐이다 — 두 번째는 게이트를 통과한 뒤에 생기고
사람의 편집과 구분되지 않는다.

당신의 커밋은 브랜치에 남아 있으니 `## 블록`에 **브랜치와 커밋 해시**를 적어라. 사람이 그걸로 넣는다.
**끝냈으면 빨리 끝내라** — 이 벽이 서 있는 동안 어떤 워커도 결과를 통합하지 못한다.
당신이 남긴 한 줄이 사람이 그걸 몇 초 만에 푸는 유일한 단서다.

**push가 성공한 뒤에 티켓을 `.done`으로 바꾼다.** 순서를 뒤집으면 통합 안 된 작업이 완료로 기록된다.

## 티켓 수명

당신의 티켓은 **이미 `.wip`로 잡혀 있다**(디스패처가 claim했다).

1. `.fs-tickets/tickets/<해시>.wip.md`를 읽는다. `## Goal`과 `## Done when`이 계약이다.
2. 수행한다. `## Done when`에 없는 일은 하지 않는다.
3. 본문 끝에 `## 결과` 절 추가 — 무엇을 바꿨는지, 검증 명령과 **실제 출력**, push한 커밋 해시.
4. `git push . HEAD:<통합 브랜치>` 성공 확인.
5. 파일명을 `<해시>.done.md`로 rename. 이 rename이 완료 신고다. **안 하면 미완으로 남는다.**

경로를 잃었으면 `ls .fs-tickets/tickets/<해시>.*`로 찾는다.
`mv`로 상태를 바꾸는 건 **자기 티켓의 `.wip` → `.done`뿐**이다.

## 티켓 성격 (`kind:`)

- `work` — 지시. 수행하고 `.done`.
- `request` — 부탁·질문. 답을 **새 `kind: feedback` 티켓**으로 만들고 원본을 `.done`.
  원본 본문에 답을 덧붙이지 않는다(원본은 질문의 기록으로 남는다).
- `feedback` — 결과보고·지적. 받은 사람이 조치 티켓을 만들거나 그냥 `.done`.

## 핸드오프

- 남의 영역 일이 생기면 **새 티켓을 만든다.** 남의 티켓을 고치지 않는다. 특히 `.wip` 티켓은
  누군가 지금 그 파일로 일하고 있다 — 절대 편집하지 않는다.
- 새 티켓에는 `persona:`를 정하고, 선후가 있으면 `deps: [<내 해시>]`로 엮는다.
  문법은 [tickets.md](tickets.md)를 읽고 쓴다. 틀리면 조용히 큐에서 사라진다.
- 넘긴 사실을 내 `## 결과`에 한 줄: `-> <새 해시> (persona) 무엇을 넘겼는지`.
- `deps`는 **없으면 착수가 불가능한 것만**. 남발하면 워커가 놀고 큐가 직렬화된다.

## 브라우저를 띄울 때 (CDP)

에이전트가 브라우저를 띄우는 프로젝트에서만 해당한다.

사람이 이 화면 앞에서 다른 일을 하고 있다. **크롬이 앞으로 튀어나오면 그 사람의 작업을 끊는다.**

- 기본은 헤드리스다. 스크린샷·클릭·폼 입력·팝오버 전부 CDP로 되고 창이 아예 안 뜬다:
  `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --remote-debugging-port=<포트> --user-data-dir=/tmp/qa-<해시>/chrome-profile --window-size=1440,900 about:blank &`
- 눈으로 볼 창이 정말 필요하면 **`open -g`로 띄운다**(창은 뜨고 포커스는 안 넘어간다):
  `open -na "Google Chrome" -g --args --remote-debugging-port=<포트> --user-data-dir=/tmp/qa-<해시>/chrome-profile --no-first-run --no-default-browser-check about:blank`
  바이너리를 직접 실행하면 앱이 활성화돼 포커스를 뺏는다 — 창이 필요할 땐 `open -g`만 쓴다.
- 포트는 세션마다 다르게(9222는 이미 다른 프로세스가 쓰고 있을 수 있다). `--user-data-dir`은 반드시
  전용 임시 경로 — 빼면 사람이 쓰는 크롬 창에 붙는다.
- **끝나면 죽인다.** 남긴 크롬은 다음 세션의 포트를 먹는다.

## 막혔을 때

추측으로 진행하지 않는다. 본문에 `## 블록` 절을 추가하고 — 무엇을 모르는지, 선택지, 무엇을
결정해줘야 하는지 — **`.wip` 그대로 두고 종료**한다. `.done`으로 바꾸지 않는다.

사람 판단이 필요한 대표 경우: 스펙이 모순된다 / 읽기 전용 영역을 고쳐야 한다 /
새 의존성이 정말 필요하다 / push가 3회 실패한다 /
티켓이 한 세션에 안 들어간다(쪼갠 티켓을 제안만 하고 멈춘다).

## 지도

프로젝트 문서를 이 표에 추가한다 — 스펙의 단일 출처, 코드베이스 규약, 그 외 착수 전에 읽을 것.

| 문서 | 무엇 |
|---|---|
| `.fs-tickets/protocols/tickets.md` | 티켓 파일 작성법. **새 티켓 만들기 전에 읽는다** |
| `.fs-tickets/personas/<이름>/PROFILE.md` | 각 역할의 권한·판단 기준 |
| `<프로젝트 스펙 문서>` | (프로젝트마다 채운다) |

## 큐의 불변식

깨지 않는다. 깨야 한다고 판단되면 `## 블록`이다.

1. **상태는 파일명.** 없음 / `.wip` / `.done` 3종. frontmatter로 옮기지 않는다(rename이 공짜 락).
2. **claim은 원자적 link.** `os.rename`으로 잡지 않는다.
3. **큐는 평면이고 사본이 하나다.** `tickets/` 아래 하위 디렉터리를 만들지 않는다.
   큐를 git에 넣지 않는다.
